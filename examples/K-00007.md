DECIDED: readings are stored as one CSV file per day, one row per frame, written append-only.
WHY: the whole dataset has to stay readable with `grep` and a text editor after a year of nobody
touching it, and the failure mode that matters here is a half-written row at power loss — which
costs one row in a CSV and can cost the file in a format with an index. Daily files also make
retention a matter of deleting files.
REJECTED: a single SQLite database — better queries, but it makes every recovery scenario depend
on a tool being installed and undamaged, and the query load is one daily summary. Rejected: one
file per month — the same argument as daily, but a corrupted tail costs thirty times more.
